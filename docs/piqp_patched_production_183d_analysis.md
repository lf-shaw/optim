## 结论

PIQP 0.6.3 dual-index 源码补丁通过生产机可靠性验证：

- wheel 为 `piqp 0.6.3+optim.dualidx1`；
- `auto` 实际解析为 compact 双边不等式；
- 8225/8225 个 PIQP QP 子问题全部返回 `PIQP_SOLVED`；
- 0 个 PIQP 子问题失败，0 次 Clarabel fallback；
- 2188 个有效日优化全部返回可用组合；
- 最大独立重算约束残差 `7.43e-9`，没有风险或换手率超限；
- 没有输出任何权重文件，整个回收归档只有 4.8 MB。

专项脚本的严格退出条件发现 1 个 factor-QP 前端证书边界点，因此完整命令理论上应以
非零状态结束，但结果已全部写出。该点不是 PIQP 求解失败，也不是源码补丁回归；它暴露的
是最终高精度重解后没有再次把 alpha certificate 收紧到配置阈值内。

SOCP 最终 QP 的原始 PIQP duality gap 因 theta/目标缩放可达到约 `1e-2`，但除以

中间容差在同一 theta 得到 TE 1.993600%，对应估算 certificate `9.9571e-5`，满足停止
条件；最终以 `1e-7` 高精度重解后 TE 轻微下降到 1.993550%，风险 slack 增加，使证书变为
`1.00353e-4`。当前代码正确地标记了 `optimal_inaccurate`，但没有再向风险边界细化。

建议在最终重解后若 certificate 超限，使用保留的风险上下界再做 final-tolerance safeguarded
secant，直到证书满足或明确失败。不要简单把该点静默视作 `optimal`。这个 gap 是标准化
alpha 目标的绝对上界，不是权重差、TE 差或直接收益 bp。

## 数据对齐与覆盖

- 183 日的风险、指数和 alpha 来源日期全部为当日，最大 stale day 为 0；
- alpha 在风险宇宙中的缺失比例为 21.93%–24.25%，缺失资产按既定规则使用零 alpha；
- 中位 alpha 缺失为 23.64%，最大日 2023-12-29 为 1236/5096；
- 风险宇宙未覆盖的指数权重为 0–0.284%，随后按既定规则在风险宇宙内归一化；
- 链式持仓映射的最大缺失质量只有 `4.44e-16`。

日期对齐本身正确，但约四分之一风险资产没有 alpha 是数据含义问题而非 solver 问题。
在把这些结果用于策略判断前，应确认 alpha 文件本来就只覆盖目标可交易池；若不是预期，
需先修复 alpha 覆盖，不能通过 solver 参数补偿。

## 内存

每个独立场景进程的初始 RSS 约 438 MB，运行链式后通常达到 631–659 MB，随后冷启动结束
时峰值约 663–669 MB。没有 OOM 或崩溃，但多数场景最后 50 日 RSS 仍以约
0.4–0.9 MB/日上升，暂时不能证明已经平台化。

这可能包含 PIQP/Eigen/native allocator 高水位、每日不同稀疏结构的内存保留，以及测试器
在内存中累计逐日 trace；当前没有权重累计。对 2500 日单进程回测不应直接线性外推，建议
在确认长期平台化前按年度或 250–500 日回收 worker 进程，并在后续 500 日以上样本继续记录
RSS P95/末段斜率。
