# CSI 2000 复现包：稠密基准下的 total_active 表达对照

## 结论

使用 `tmp/pp_20260814_csi2000.tar.gz` 完成补测。精确稀疏表达仍有效，但 Clarabel 总耗时下降约 **15.1%**，
原生求解时间下降约 **29.3%**，收益小于此前 300 只基准成分股样本的约 60%。
本批原表达的迭代数已较稳定；改写主要降低单次迭代成本，而非大幅减少迭代次数。

本机没有复现“原版 auto 比 MOSEK 更快”：原始 8% 预算下，不覆盖后端线程设置，
总耗时中位数为 auto **0.525 秒**、MOSEK **0.474 秒**，已经处于相近量级。
这不否定生产机上的观察；硬件、构建版本和计时范围都可能改变小幅排序。
不能据本批结果承诺两者在所有场景下固定快慢。

仍然只有实验代码和文档变更，没有修改生产编译器或求解器默认设置。

## 1. 新包实际内容与对照边界

| 项目 | 新复现包 | 此前 08-14 包 |
|---|---|---|

| total_active | 1.0 | 1.8 |
| 换手率约束 | L1 上限 2.0 | 未配置 |

新包初始持仓有 500 只股票，初始持仓与基准的 L1 距离为 2.0；330 只股票不可交易。
生产编译器已经使用 `exact_sparse_turnover`，产生 500 个换手辅助变量。
本轮保留其换手率、风格、行业、个股主动权重及覆盖率设置，仅按实验计划改变 TE 预算或 total_active 表达。

因此新旧样本不是“仅更换基准”的严格 A/B 对照，不能将求解路径差别全部归因于基准变密。
这里比较同一个新包内不同表达，避免混淆。

## 2. 固定单线程：120 次正式对照

五档 TE 预算、四种表达、auto/MOSEK 两个后端、每组重复三次，共 120 次。
独立冷启动，固定种子交错排列，预热和复现包读取不计入。
auto 的实际后端全部为 `clarabel_qdldl`。
表中耗时为总墙钟时间的中位数，单位为秒，包含编译、原型裁剪、结果验收及默认权重清理。

| TE 预算 | auto 原表达 | auto 稀疏表达 | 原/稀疏迭代数 | MOSEK 原表达 | MOSEK 稀疏表达† |
|---|---:|---:|---:|---:|---:|
| 2% | 0.435 | 0.395 | 23 / 25 | 0.369 | 0.290 |
| 4% | 0.499 | 0.424 | 25 / 26 | 0.454 | 0.292 |
| 6% | 0.531 | 0.425 | 31 / 28 | 0.472 | 0.306 |
| 8% | 0.504 | 0.416 | 28 / 27 | 0.464 | 0.330 |
| 10% | 0.522 | 0.456 | 29 / 28 | 0.463 | 0.354 |
| 各案例中位数的均值 | **0.498** | **0.423** | 27.2 / 26.8 | **0.444** | **0.315** |

† MOSEK 稀疏表达的这些结果存在超过 $10^{-5}$ 的实际 L1 超限，不能作为同业务精度的合格耗时比较。见第 4 节。

完整正负分解的 auto 平均总耗时为 0.504 秒，略慢于原表达；仍不如精确稀疏单边表达。
后者平均原生求解时间由 0.347 秒降至 0.245 秒。
原型仍先建立完整域再裁剪，不是最终生产编译流程，因此前端未充分受益。

### 模型规模

最终边界分类中，有 1961 只股票可能跨越基准权重，3247 只股票确定不会低配，没有确定一直低配的股票。

| 表达 | 总变量 | 总行数 | 矩阵非零元 |
|---|---:|---:|---:|
| 原始 epigraph | 10963 | 32439 | 156814 |
| 精确稀疏单边 | 7716 | 20737 | 133410 |
| 完整正负分解 | 16171 | 32439 | 162022 |
| 移除 total_active，仅作消融 | 5755 | 16814 | 125566 |

辅助变量只从 5208 个降至 1961 个，而非此前降至 300 个，且原表达没有此前明显的高预算迭代增长。
这两点与加速幅度较小一致；不能单凭维度给出更强的算法因果结论。

## 3. 原始 8% 预算，不覆盖后端线程设置

对 auto、显式 Clarabel、MOSEK，分别运行原表达和稀疏表达，每组七次，共 42 次正式求解。
BLAS 线程仍固定为 1，只取消实验对原生求解器线程设置的覆盖。

| 请求后端 | 原表达总耗时 | 稀疏表达总耗时 | 原表达迭代数 | 稀疏表达迭代数 |
|---|---:|---:|---:|---:|
| auto | 0.525 | 0.420 | 28 | 27 |
| clarabel | 0.507 | 0.427 | 28 | 27 |
| mosek | 0.474 | 0.341† | 21 | 36 |

auto 和显式 Clarabel 的后端、迭代数及目标值相同，几毫秒到十几毫秒的耗时差不能解读为路由的稳定额外成本。
MOSEK 原表达的 CPU 时间中位数约为 0.797 秒，大于 0.474 秒墙钟时间，确实用到了额外 CPU；本机并未因此获得明显更低延迟。
此处 † 同样表示实际 L1 超限，不能用该行宣称保持相同业务精度的加速。

## 4. 从最终持仓独立复算质量

本轮确认该 total_active 真正起限制作用：移除后，auto 的实际 L1 约为 **1.523–1.886**，远高于原上限 1.0。
这些移除后的解只属于变化后的问题，不能作为原问题的替代答案。

保留约束含义的稀疏 auto：

- 与原表达相比，目标值最大绝对差约 $4.11\times10^{-8}$。
- 实际 L1 最大超限约 $1.11\times10^{-6}$，低于 $10^{-5}$ 业务验收阈值。
- 五档预算全部返回可行数值候选，并保持风险预算精度。

MOSEK 的实际总量检查仍暴露累积残差：

| 表达 | 最大实际 L1 超限 |
|---|---:|
| 原表达 | $1.06\times10^{-5}$（10% 预算略超） |
| 稀疏单边 | $1.85\times10^{-4}$ |
| 完整正负分解 | $2.30\times10^{-4}$ |

API 当前均返回 `optimal`，但它们的逐行残差不足以保证实际总量在同一容差内。
因此继续保留上份报告的集成要求：从最终持仓复算 L1 并用于验收，而非只把其作为展示指标。
本轮没有为通过检查而修改 MOSEK 容差、裁剪超限或偷偷放宽业务上限。

## 5. 复现与产物

脚本已增加 `--repro`、`--budgets`、`--backends`、`--threads`，不再必须使用内置两个样本。
仍不输出权重。输入说明、每次耗时、实际后端、CPU 时间和独立质量统计保存在输出目录。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python benchmarks/total_active_ablation.py \
  --repro tmp/pp_20260814_csi2000.tar.gz --backends auto,mosek \
  --variants baseline,sparse,split,removed --rounds 3 \
  --output tmp/csi2000_forms_repeat

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python benchmarks/total_active_ablation.py \
  --repro tmp/pp_20260814_csi2000.tar.gz --backends auto,clarabel,mosek \
  --variants baseline,sparse --budgets 0.08 --threads 0 --rounds 7 \
  --output tmp/csi2000_native_repeat
```

本机产物：`tmp/csi2000_active_forms_20260909`、`tmp/csi2000_native_threads_20260909`。
正式运行共 162 次。原型相关 17 项测试再次通过；未修改生产模块或提交版本。
