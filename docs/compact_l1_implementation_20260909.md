# 紧凑 L1 与安全冗余消除：实施记录

本文件供仓库内审阅。模型表达、消除条件和数值处理细节不进入公共 API docstring 或 AI 知识库。
后端名称、默认高层路由和诊断使用方法继续公开；它们属于用户需要核查的运行信息。

## 1. 实施范围

已实施两个获准方向，固定资产消元仍暂缓：

1. 根据最终有效资产边界与预算，省略可证明冗余的换手率/总主动 L1 行及其辅助变量。
2. 正常只做多问题直接规划总主动权重的紧凑列布局，不先生成完整域再裁剪。

不改变用户目标、预算、风险单位、换手率口径、默认路由或业务可行性容差。
LP 仍为 HiGHS，QP 仍为 direct PIQP，风险预算问题仍为 Clarabel；MOSEK 仅显式使用。
`total_active` 按此前约定要求有限且严格大于零，`None` 禁用；没有写死 0.2 等业务下限。

## 2. 编译与安全条件

`resolve_asset_bounds` 在布局规划前执行一次，后续变量上下界和布局分类复用同一结果。
不只检查 `long_only=True`：操作指令可能保留负的冻结持仓，必须检查最终非负边界。
允许卖空的请求暂保留完整总主动 epigraph，避免将实验收益外推到所有问题。

### 2.1 冗余证明

对于中心 $c$、预算 $\sum_i w_i=B$ 和最终边界 $l\le w\le u$：

- 若最终权重非负，则 $\|w-c\|_1\le B+\|c\|_1$。
- 有限盒边界给出 $\|w-c\|_1\le\sum_i\max(|l_i-c_i|,|u_i-c_i|)$。
- 保留原有由换手率与初始主动距离推得的总主动上界。

仅当计算出的上界不大于用户上限时省略；不加业务验收容差，也不根据某次候选上约束不活跃判定。
使用稳定求和减少浮点累计误差，但这些实现仍是浮点运算，不是有理数形式化证明系统。
基准覆盖率的既有换手推界加入预算与初始权重总和差的修正，不再隐含二者必然相等。

`compiler_optimizations` 记录省略/表达选择；原始问题对象和业务指纹不改变。
编译器版本更新为 `portfolio-canonical-v4-compact-l1`，canonical hash 允许改变。

### 2.2 直接总主动布局

使用恒等式：

$$
\|w-b\|_1=B-\sum_i b_i+2\sum_i(b_i-w_i)_+.
$$

最终区间确定高配的项贡献为零；确定低配的项直接进入总量行；只有跨基准的项创建非负辅助列。
不使用容差对符号分类；即使辅助列为空，也不能丢弃确定低配项和常数。
所有原始股票列仍保留，未实现固定资产消元。

辅助变量 key 保留真实股票坐标；QP 因子列一次分配到最终位置，不需要事后重排。
总量行记录 `expression_offset`，展示和验收时恢复业务坐标。
权重清理后的 `lift_weights` 同步重建新的低配辅助量。

### 2.3 诊断与验收

诊断域 `simplify=False` 保留完整换手、总主动及可放宽约束，不使用依赖原约束的消除。
正常求解最终仍从持仓复算换手、总主动与基准成分覆盖，即使对应行已被省略。
新测试构造了每个 epigraph 行仅 $4\times10^{-6}$ 的残差、但 L1 累计违约达到
$1.6\times10^{-5}$ 的候选，确保它不能通过 $10^{-5}$ 业务验收。

## 3. 真实案例耗时

输入为两个 2026-08-14 复现包，5208 只资产、47 个因子，基准分别含 1000/1961 只正权重股票。
保持包内总主动上限 1、L1 换手上限 2、其他线性约束不变；LP/QP 不含风险预算，SOCP 为年化 8%。
QP 因子与特异风险惩罚系数均为 0.75。

同机前后各五次独立冷启动，固定数值库/后端线程，以下为公共 `solve()` 的中位数，单位秒。
不计数据包加载与统计导出；无权重文件；前后未并行运行编译或测试。

| 基准 | 问题 | 改前 | 改后 | 原生求解改前→改后 |
|---|---|---:|---:|---|
| CSI1000 | LP | 0.224 | 0.119 | 0.123 → 0.069 |
| CSI2000 | LP | 0.318 | 0.191 | 0.211 → 0.138 |
| CSI1000 | QP | 0.261 | 0.109 | 0.148 → 0.050 |
| CSI2000 | QP | 0.258 | 0.124 | 0.135 → 0.059 |
| CSI1000 | SOCP 8% | 0.578 | 0.239 | 0.440 → 0.159 |

两组 SOCP 的 Clarabel 迭代分别从 37→21、28→22；变量列从 10963 降至 6255/7216。
收益包含删除冗余的 200% 换手上限，不应直接外推到紧换手上限。
此前裁剪原型与现在直接编译的运行不是同一次计时实验，不将两者差值全算作前端净收益。
真实生产机器仍需用同样数据复测，不承诺固定加速比例。

改后 30 次主实验全部 optimal；LP 目标一致，QP 目标值最大差约 $4.22\times10^{-10}$，
SOCP 最大差约 $1.17\times10^{-8}$。

## 4. 扩展回归与 MOSEK 数值处理

自动后端另测试两个基准、2%/4%/6%/8%/10% 风险预算，以及总主动上限 0.01 和允许单股 -1%
卖空的场景，共 42 次，全部通过既定验收。紧总主动未设特殊切换阈值。

统一业务总量验收暴露了 MOSEK 原生默认精度的问题：初次 30 次风险扫描中，27 次虽原生成功，
但 L1 累计违约超过 $10^{-5}$，被返回为 numerical_error。不能把它们计为有效性能结果。
这与此前稀疏表达实验中观察到的 MOSEK 总量偏差一致，并非放宽验收即可忽略的问题。

安装版进一步检查发现 Task QP 也存在同类累计误差，因此 Task/Fusion 使用同一个精度请求函数。
有 L1 约束时使用不高于 $10^{-10}$ 的原生 primal 可行性阈值；若请求更严格则遵守请求。
分别映射到 LP/QP/锥问题对应的原生参数。无 L1 问题不加这一上限，未改目标 gap 或放宽业务容差。
实际阈值记入后端诊断元数据。此阈值不是所有问题的总量误差保证，最后仍独立验收。

修改后同样的 MOSEK 风险扫描 **30/30 通过**，最大总主动违约约 $8.92\times10^{-6}$。
另两个真实案例的显式 MOSEK LP/QP 均通过，QP 最大观测违约约 $7.90\times10^{-6}$。
年化 8% 时，MOSEK 总耗时中位数分别约 0.205/0.233 秒；该组是数值修复后的独立复跑，
不与上表自动路线构成同进程交错性能排名。
